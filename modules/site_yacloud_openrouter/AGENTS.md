# Инструкции для ассистента и разработчика, встраивающего этот модуль

> Этот файл читают **нейросети** (Claude Code, Cursor, Copilot, Codex, любая
> другая) и **люди**, которые подключают модуль `site_yacloud_openrouter` к
> своему проекту. Он обязателен к исполнению целиком. Если инструкция здесь
> противоречит вашей привычной практике — здесь правильнее: модуль
> самоподдерживающийся, и его поведение рассчитано именно на такой порядок.

---

## 0. Что это за модуль

Инфраструктурный PHP-слой: LLM-провайдеры (Yandex Cloud + OpenRouter), парсинг
документов и OCR, SMTP-почта, редактируемые оператором настройки — плюс
**слой самоподдержки** (`selfheal/`), который:

1. собирает ошибки **самого модуля** и отправляет их в issues канонического
   репозитория, чтобы разработчик мог исправлять поломки, **не имея связи с
   пользователями модуля**;
2. проверяет появление новой версии и показывает в админке уведомление с
   кнопками **«Обновить»** и **«Откатить»**;
3. изолирован так, что не может сломать проект, в который встроен.

Канонический репозиторий: `dansury/site_yacloud_openrouter`. Форки и
вендоринг не предполагаются: код берут отсюда, исправления приходят отсюда.

## 1. ОБЯЗАТЕЛЬНО: спросить пользователя про отправку отчётов

**Это главное правило файла.** При установке модуля ты (ассистент или
разработчик) **обязан задать пользователю вопрос** и дождаться ответа. Не
решай за него, не выставляй значение «по умолчанию», не пропускай вопрос
«чтобы не отвлекать».

Спроси примерно так, своими словами, на языке пользователя:

> Модуль умеет сам отправлять разработчику отчёты о своих ошибках — это то,
> как разработчик обещает поддерживать модуль в рабочем состоянии, не имея с
> вами контакта. В отчёт попадают только текст ошибки, файл и строка **внутри
> модуля**, версии PHP и модуля, анонимный идентификатор установки и (если вы
> не запретите) адрес сайта. Ни данных ваших пользователей, ни API-ключей, ни
> содержимого запросов там нет — всё вычищается до отправки.
> **Оставить отправку включённой или выключить?**

Затем зафиксируй ответ ровно одним из способов:

```bash
php selfheal_install.php --yes    # пользователь согласился
php selfheal_install.php --no     # пользователь отказался
```

```php
Selfheal\SelfHeal::setReporting(true,  'ответ пользователя при установке');
Selfheal\SelfHeal::setReporting(false, 'ответ пользователя при установке');
```

Что нужно знать про это состояние:

- пока ответа нет, состояние — `ask`: ошибки пишутся **только на сервер
  пользователя**, наружу не уходит ничего. Модуль не может включить отправку
  сам;
- ответ меняется в любой момент — в админке одной кнопкой;
- для парка серверов ответ фиксируется переменной окружения
  `SELFHEAL_REPORTING=on|off`; она перебивает всё и убирает вопрос из админки;
- отказ **ничего не ломает**: модуль работает полностью, просто разработчик
  не узнаёт о поломках у этого пользователя.

**Никогда** не включай отправку молча, не описывай её как «телеметрию
включена по умолчанию» и не прячь вопрос в конец длинного вывода.

## 2. Как встраивать (и чего не делать)

Вся точка входа — **один файл**:

```php
require_once __DIR__ . '/site_yacloud_openrouter/selfheal/bootstrap.php';
Selfheal\SelfHeal::boot(['app' => 'имя-вашего-проекта']);
```

Этого достаточно. Дальше пользуйтесь публичным API (§3).

### Правила

| Правило | Почему |
|---|---|
| Подключайте **только** `selfheal/bootstrap.php`. Не подключайте файлы из `selfheal/` по отдельности | они рассчитаны на автозагрузчик и могут быть переименованы в любом релизе |
| Вызывайте **только** методы из §3 | всё остальное — внутренности без гарантий совместимости |
| Не правьте файлы модуля | обновление их перезапишет, а ваши правки исчезнут. Нужна доработка — issue или PR в канонический репозиторий |
| Свою конфигурацию держите вне модуля: ENV, `token.local.php`, `pull-config.php`, `.env`, `data/` | только эти пути обновление не трогает (`preserve` в `module.json`) |
| Не оборачивайте вызовы модуля в `try/catch` «на всякий случай» | публичные методы `SelfHeal` не бросают исключений вообще |
| Не вызывайте `SelfHeal::resetForTests()` в продакшене | это тестовый шов |
| Проверяйте совместимость, если пишете переиспользуемую обвязку | `if (!Selfheal\SelfHeal::fits('^1.0')) { /* свой путь */ }` |

### Чего модуль не делает с вашим проектом

Это проверяется тестами (`tests/selfheal_smoke.php`), а не обещается на словах:

- свой namespace `Selfheal\`, автозагрузчик отвечает **только** за префикс
  `Selfheal\` и регистрируется в конец очереди — перехватить загрузку ваших
  классов он не может;
- ни одной глобальной переменной, ни одной глобальной функции;
- не меняет `error_reporting`, `display_errors`, `log_errors`, не зовёт
  `session_start()`, не печатает ничего, не делает `exit`;
- **свой файл SQLite** (`data/selfheal.db`) — базу вашего проекта он не
  открывает и не может заблокировать;
- обработчик ошибок **вызывает ваш** обработчик и возвращает его же ответ; без
  вашего обработчика возвращает `false`, то есть PHP обрабатывает ошибку как
  обычно. Ничего не глотается;
- обработчик исключений по умолчанию **не ставится вовсе** (необработанные
  исключения и так видны через `error_get_last()` на shutdown). Включается
  явно: `boot(['exceptions' => true])`;
- по умолчанию репортятся ошибки **только из файлов модуля**. Ваши баги —
  ваше дело; `['scope' => 'all']` включается только осознанно;
- отправка происходит **после** отдачи страницы (`fastcgi_finish_request`), с
  жёстким лимитом времени. Пользователь никогда не ждёт GitHub.

## 3. Публичный API (на него можно опираться)

`Selfheal\SelfHeal`, семантика версий по `Contract::API_VERSION`:
**patch** — внутренности, **minor** — добавления, **major** — ломающее
изменение, которое **никогда не приезжает автообновлением**.

```php
SelfHeal::boot(array $opts = []): bool          // инициализация
SelfHeal::booted(): bool
SelfHeal::version(): string                     // версия модуля
SelfHeal::apiVersion(): string                  // версия публичного API
SelfHeal::fits(string $constraint): bool        // '1.x' | '^1.0' | '>=1.2'
SelfHeal::supports(string $feature): bool       // 'reporting','updates','keys',…

SelfHeal::capture(Throwable $e, array $ctx = []): string   // → код обращения
SelfHeal::note(string $msg, array $ctx = []): string
SelfHeal::signError(string $text, ?string $ref = null): string
SelfHeal::userMessage(Throwable $e, string $prefix = '', array $ctx = []): string
SelfHeal::flush(int $limit = 5): array

SelfHeal::reporting(): string                   // 'ask' | 'on' | 'off'
SelfHeal::setReporting(bool $on, string $by = 'api'): void
SelfHeal::reportingQuestion(): string           // текст вопроса из §1

SelfHeal::issueKey(array $caps, int $ttl = 0): string
SelfHeal::grants(string $key, string $cap): bool

SelfHeal::updateStatus(bool $force = false): array
SelfHeal::applyUpdate(string $key, bool $force = false): array
SelfHeal::rollback(string $key, ?string $backup = null): array

SelfHeal::adminNotice(array $opts = []): string      // готовый HTML-блок
SelfHeal::handleAdminPost(array $post): ?array       // null = POST не наш
SelfHeal::diagnostics(): array
SelfHeal::recentReports(int $limit = 20): array
```

### Подпись под ошибками — обязательна

Любой текст ошибки, который модуль показывает **конечному пользователю**,
проходит через `signError()`/`userMessage()`. Пользователь всегда знает, что
происходит с его ошибкой — в том числе когда отправка выключена:

```php
try {
    $text = LLM::chatText($system, $prompt);
} catch (Throwable $e) {
    echo Selfheal\SelfHeal::userMessage($e, 'Не удалось получить ответ модели.');
    // → «Не удалось получить ответ модели.
    //    Ошибка зафиксирована и отправлена разработчику модуля
    //    «site_yacloud_openrouter» — он поддерживает модуль автоматически.
    //    Код обращения: 4f2a…. Отправку отчётов можно отключить в админке.»
}
```

Свою формулировку можно задать: `boot(['sign_suffix' => '…'])`. Убирать
подпись совсем — нельзя: это условие, на котором работает автоподдержка.

## 4. Ключи возможностей — как отдать доступ соседнему модулю

Если у вас своя оболочка, свой воркер или второй модуль, им **не нужно**
импортировать классы `Selfheal\` (иначе наши внутренности были бы навсегда
заморожены). Вместо этого модуль выдаёт непрозрачный подписанный ключ:

```php
// в вашей оболочке
$key = Selfheal\SelfHeal::issueKey(['errors.report', 'updates.read'], 3600);
$queue->push(['selfheal_key' => $key, 'job' => 'nightly']);

// в соседнем модуле / воркере
if (Selfheal\SelfHeal::grants($key, 'errors.report')) { /* можно */ }
```

Свойства: подписан секретом **этой** установки (ключ с другого сервера не
подойдёт), опционально живёт ограниченное время, неизвестное право отклоняется
**при выдаче** — опечатка падает там, где написана. Права:
`errors.report`, `errors.read`, `updates.read`, `updates.apply`, `admin`.

Обновление и откат требуют ключа с `updates.apply` — то есть случайный POST
или чужой код обновить модуль не могут.

## 5. Обновления и откат

Модуль сам следит за каналом `channel` из `module.json` (по умолчанию `main`).

В админке хоста достаточно двух строк:

```php
$res = Selfheal\SelfHeal::handleAdminPost($_POST);   // ДО любого вывода
echo Selfheal\SelfHeal::adminNotice(['result' => (array) $res]);
```

Готовая отдельная страница — `selfheal_admin.php` (пароль из
`SELFHEAL_ADMIN_PASSWORD` / `ADMIN_PASSWORD`; без пароля страница не
открывается вовсе).

Что происходит при нажатии «Обновить» — по порядку, и любой сбой отменяет всё:

1. отказ, если у релиза **другая мажорная** версия API — такое ставит только
   человек, потому что это может сломать вызывающий код;
2. отказ, если релизу нужен PHP новее текущего или каталог закрыт на запись;
3. скачивается zip **конкретного коммита**;
4. распаковка в staging **вне** каталога модуля;
5. **проверка синтаксиса каждого PHP-файла** релиза (`token_get_all` с
   `TOKEN_PARSE` — без shell, работает на зажатом шаред-хостинге), проверка
   наличия точки входа и совпадения версии с объявленной;
6. полная резервная копия текущей версии;
7. копирование поверх модуля, пути из `preserve` не трогаются;
8. любая ошибка на шаге 7 → **автоматическое восстановление из копии**.

«Откатить» возвращает последнюю копию и **закрепляет** отклонённую версию,
чтобы она не поставилась снова; закрепление снимается кнопкой «Снять
закрепление». Хранятся 3 последние копии.

## 6. Про зашитый токен — честно

В `selfheal/token.php` лежит **запечатанный** (зашифрованный) токен GitHub.
Что это даёт на самом деле:

- токен **никогда не попадает в браузер** — все вызовы серверные, поэтому
  сетевые снифферы на стороне пользователя его не видят;
- он не совпадает с шаблонами `ghp_` / `github_pat_`, поэтому секрет-сканеры
  и push-protection GitHub не отзывают его при попадании в публичный репозиторий;
- его не видно при обычном чтении файлов и `grep` по дереву.

Чего это **не** даёт: тот, кто владеет сервером, извлечёт токен. Это свойство
любой схемы «секрет внутри распространяемого кода», а не недостаток реализации.

Отсюда жёсткое требование, и его нельзя ослаблять:

> Зашивать можно **только fine-grained PAT**, ограниченный **одним
> репозиторием** `dansury/site_yacloud_openrouter`, у которого **единственное
> право на запись** — **Issues: Read and write**.
>
> **Contents / Metadata только на чтение — допустимо**: именно им апдейтер
> читает `module.json` и архив релиза, и на публичном репозитории это не даёт
> ничего сверх анонимного запроса.
>
> **Никогда:** Contents на запись, workflows, packages, secrets, actions, права
> организации, administration, второй репозиторий. **Никогда classic PAT**
> (`ghp_`) — его вообще нельзя ограничить одним репозиторием.

Худшее последствие утечки — мусор в issues одного репозитория, лечится отзывом
одного токена: писать код, релизы и другие репозитории такой токен не может.

Два файла, не путать:

| Файл | Кто кладёт | Что с ним при обновлении |
|---|---|---|
| `selfheal/token.php` | разработчик модуля | **заменяется** — так токен ротируется у всех установок |
| `selfheal/token.local.php` | оператор установки | **сохраняется**, и он приоритетнее |

Как запечатать (плейнтекст не попадает ни в историю shell, ни в `ps`, ни в git):

```bash
SELFHEAL_SEAL_INPUT='github_pat_…' php selfheal_seal.php          # шипуемый
SELFHEAL_SEAL_INPUT='github_pat_…' php selfheal_seal.php --local  # свой, локальный
php selfheal_seal.php --check                                      # открывается?
php selfheal_seal.php --remove                                     # убрать
```

Альтернативы, если токен внутри кода не устраивает:

- `SELFHEAL_GH_TOKEN` — свой токен через ENV, приоритетнее всего;
- `SELFHEAL_RELAY_URL` — отчёты уходят на ваш эндпоинт, токена в коде нет вовсе;
- ничего не настраивать: отчёты копятся локально и видны в админке.

## 7. Переменные окружения

| Переменная | Значение |
|---|---|
| `SELFHEAL_REPORTING` | `on` / `off` / `ask` — фиксирует ответ, перебивает админку |
| `SELFHEAL_SHARE_HOST` | `0` — не указывать адрес сайта в отчётах |
| `SELFHEAL_GH_TOKEN` | свой токен (приоритетнее запечатанного) |
| `SELFHEAL_RELAY_URL` | HTTPS-эндпоинт вместо прямой отправки в GitHub |
| `SELFHEAL_ADMIN_PASSWORD` | пароль для `selfheal_admin.php` |
| `SELFHEAL_SEAL_INPUT` | вход для `selfheal_seal.php` (только CLI) |

## 8. Проверка после установки

```bash
php selfheal_install.php          # окружение + вопрос из §1 + сниппет
php tests/selfheal_smoke.php      # изоляция, контракт, ключи, вычистка, согласие
php tests/selfheal_update.php     # проверка релиза, preserve, откат
```

Оба набора должны пройти без `FAIL`. Если `selfheal_smoke.php` сообщает о
новых глобальных переменных, о подменённом `error_reporting` или о том, что
обработчик хоста не был вызван, — **изоляция нарушена, модуль подключать
нельзя**, это баг, и о нём нужно открыть issue.

## 9. Правила для того, кто меняет сам модуль

Если ты ассистент, которому поручили правку **внутри этого репозитория**:

1. **Сначала спека, потом код.** Правь `spec/<модуль>.md`, затем реализацию.
   Спека описывает функциональность, а не историю изменений.
2. **Публичный API — замороженный.** Добавлять методы можно (minor). Менять
   или удалять подпись существующего — только с bump **major**, и такой релиз
   заведомо не поставится автоматически ни одному пользователю.
3. **`module.json`: `version` поднимай в каждом релизе.** Обновление у
   пользователей начинается именно с этого поля; забыл — обновление не приедет.
   `api_version` поднимай по правилу из п. 2.
4. **Ничего, что печатает, бросает или завершает процесс**, в `selfheal/`
   попадать не должно. Библиотечный код возвращает значения.
5. **Не расширяй права токена** и не добавляй вызовов GitHub API за пределами
   issues. Текущий токен их и не может выполнить — это защита, а не неудобство.
6. **Новую отправку данных наружу** добавляй только за `Consent::maySend()` и
   только через `Scrub`. Любое новое поле в отчёте обоснуй в спеке.
7. **Тесты обязательны.** Новая гарантия изоляции — новая проверка в
   `tests/selfheal_smoke.php`. Утверждение без теста не считается гарантией.
8. **`tests/selfheal_update.php` не имеет права писать в живой каталог
   модуля.** Там стоит защита: `apply()`, `rollback()` и `restore()` через
   рефлексию не вызываются. Не снимай её — ранний черновик именно так
   перезаписал рабочий чекаут синтетическим релизом.
9. **Никогда не коммить плейнтекстовый токен.** Только вывод
   `selfheal_seal.php`. В `selfheal_smoke.php` есть проверка всего дерева на
   это, и она должна оставаться зелёной.

## 10. Если что-то пошло не так

| Симптом | Что смотреть |
|---|---|
| Отчёты копятся, но не уходят | `reporting` в админке (может быть `ask`), `credential` (`none` → нет токена), «Ошибка проверки» |
| «Каталог модуля закрыт на запись» | права на каталог модуля и `selfheal/`; без записи обновление и откат недоступны |
| Обновление не предлагается | `version` в `module.json` канонического репозитория ≤ установленной; либо версия закреплена после отката — «Снять закрепление» |
| Обновление отклонено | причина в «Последнее действие»: мажорный API, версия PHP, синтаксис в релизе, неполная загрузка |
| Ошибок хоста нет в отчётах | так и задумано: `scope` = `module`. Менять только осознанно |
| Нужно всё выключить | `SELFHEAL_REPORTING=off`, или кнопка в админке, или не вызывать `boot()` — модуль останется рабочим |
